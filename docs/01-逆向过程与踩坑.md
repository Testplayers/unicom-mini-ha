# 01 · 逆向过程与踩坑记录

> 场景：Home Assistant 里已有的联通集成全部失效（`getTicket failed: code=9999`）。
> 下面是把它一步步救活的全过程：怎么排除网络问题、怎么发现"鉴权换成了 RSA"、怎么从小程序包里挖出公钥、以及一路上每个报错到底意味着什么。

实测环境：HAOS 2026.9（Core 2026.9.3）+ 微信 PC 小程序 `wx56af9763578b9a93`（版本号 494）。

---

## 阶段 0：现象与第一层判断

日志里反复出现：

```
ERROR [custom_components.ha_unicom_bill.api] Failed to get usage detail: 'int' object has no attribute 'get'
WARNING [custom_components.ha_unicom_bill.api] getTicket failed: code=9999
WARNING [custom_components.ha_unicom_bill.api] sspbigball error: {'msg': '首页大球调用异常', 'code': '9999'}
```

**先分清是"网络不通"还是"服务端拒绝"**，这决定了后面所有排查方向：

```
# 之前的现象：Cloudflare 524（超时，后端挂了）
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' \
  -X POST -H 'Content-Type: application/json' \
  -d '{"openid":"x","channel":"wxmini"}' \
  https://mina.10010.com/wxapplet/weixinNew/getTicket
# → 524 0.23s

# 后端恢复后：0.2 秒返回业务错误（说明服务端在正常处理，只是拒绝我们）
# → 400 / {"code":"9999"}
```

结论：**不是网络问题，是请求被拒**。

---

## 阶段 1：手工重放，确认"明文 openid 被拒"

直接用集成里配置的明文 openid 重放三个接口（带小程序同款请求头）：

```
getTicket      + 明文 → {"msg":"????ticket????","code":"9999"}
sspbigball     + 明文 → {"msg":"首页大球调用异常","code":"9999"}
queryGoodsList + 明文 → {"msg":"满卡满融接口调用异常","code":"9999"}
```

注意 `msg` 里的 `????`：**联通服务端把中文转丢了**（返回体里是真正的 0x3F 字节），
所以后面不要指望靠文案定位问题，只能看 `code`。

---

## 阶段 2：抓包对比 —— 发现 openid 根本不是明文

用 mitmproxy 抓一次微信 PC 小程序的完整会话，然后对比"我们发的"和"它发的"：

```
findOpenid 响应（明文）: {"code":"0000","unionid":"oAxk...","openid":"oFroJ0ZkvVVZPkAIA0AV5wRU2eOY"}
sspbigball 请求体      : {"openid":"ZM7wkaQQCAg9Hsu7WZDPzTfthQ4XqkRnQVIAFkD0dx+7zp...","channel":"wxmini"}
                                             ^^^ 344 字符
```

继续比对，发现同样的现象出现在**几乎所有接口**（`getToken` / `getTicket` / `queryGoodsList` /
`queryGoodsGeneral` / `zopGoodNumberQuery` / `queryNearHallByAddress` …），而且：

```
两次 sspbigball 的 openid 密文 → 完全不同
所有密文长度 → 都是 344 字符
base64 解码 → 都是 256 字节，且字节分布随机（无公共前缀、无重复片段）
```

**256 字节 + 每次随机 = 教科书式的 RSA-2048**。

---

## 阶段 3：找出"加密的是什么"和"公钥在哪"

### 3.1 公钥从客户端包里挖

明文 openid 不可能凭空出现在密文里，加密逻辑一定在客户端。PC 微信的小程序包就在本机：

```
%APPDATA%\Tencent\xwechat\radium\users\<user>\applet\packages\<appid>\<ver>\__APP__.wxapkg
# 本例：...\applet\packages\wx56af9763578b9a93\494\__APP__.wxapkg（3.5 MB）
```

该文件以 `V1MMWX` 开头 —— PC 微信的加密格式，解密算法（参考 `pc_wxapkg_decrypt_python`）：

1. `key = PBKDF2-HMAC-SHA1(password=appid, salt="saltiest", iterations=1000, dklen=32)`
2. 用 `AES-256-CBC(key, iv="the iv: 16 bytes")` 解密**前 1024 字节**（跳过 6 字节 magic）
3. 其余字节**逐字节异或** `ord(appid[-2])`（本例 appid 倒数第二个字符是 `9` → `0x39`）
4. 拼接：`明文[0:1023] + 异或后的尾部`

解密后首字节应为 `0xBE`（标准 wxapkg）。解包共 **531 个文件**，然后在 JS 里搜加密关键字：

```js
// app-service.js
getRsa: function () {
  var t = new o;                      // JSEncrypt
  return t.setPublicKey("MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA7vCN/AU3...");
}
```

→ **2048 位公钥（392 字符 base64，DER/SPKI）**，这就是全部秘密（公钥本来就是公开的）。

### 3.2 加密的明文是什么

在 `app-service.js` 里找调用点，三处都长这样：

```js
// 首页大球 / 流量话费详情页
getdqiu: function () {
  var a = wx.getStorageSync("openid"), t = wx.getStorageSync("token");
  i = { openid: n.getRsa().encrypt("".concat(t).concat(a)), channel: "wxmini" };
  wx.request({ url: ... + "weixinNew/sspbigball", method: "POST", data: i, ... })
}
```

即：**明文 = `token + openid` 字符串拼接**（`openid` 取自本地存储，`token` 来自 `getToken`，首次为空串）。
所以第一句请求（`getToken`）等价于 `RSA(openid)`。

## 阶段 4：Python 复现加密 → 链路逐段打通

```python
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives.asymmetric import padding
import base64

pub = serialization.load_der_public_key(base64.b64decode(PUBKEY_B64))
enc = lambda s: base64.b64encode(pub.encrypt(s.encode(), padding.PKCS1v15())).decode()
```

（JSEncrypt 默认就是 PKCS#1 v1.5 填充；密文长度 256 字节 → base64 344 字符，与抓包完全一致。）

逐段验证：

```
1) getToken( {"openid": enc(openid)} )
   → {"code":"0000","data":"UILlTIvI87DEBB0Mo%2FzhhO...  '}
                              ^^^ 注意：返回体是 URL 编码的，使用前要 unquote
2) sspbigball( {"openid": enc(token + openid)} )
   → 一开始一直 {"msg":"获取用户绑定信息异常","code":"1002"}
```

`1002` 是这条路上的**关键卡点**：密文解密成功了（否则报的是别的错），
但服务端"找不到这个用户的绑定信息"。

追 `findMobileByOpenid`（小程序里建立 openid↔手机号 绑定的那一步）：

```js
// app-service.js
findMobileByOpenid: function (o, n, i) {
  var s = wx.getStorageSync("token");
  wx.request({ url: ... + "findMobileByOpenid/wx/wxmini",
               data: { openid: t.getRsa().encrypt("".concat(s).concat(o)), code: n } })
}
```

它需要一个 `code` —— **微信 `wx.login()` 的一次性登录码**。实测：

```
findMobileByOpenid + code=""      → {"msg":"鉴权失败","code":"1001"}
findMobileByOpenid + code="test"  → {"msg":"鉴权失败","code":"1001"}
```

服务端要用这个 code 去微信那边换 openid，证明"调用者确实是这个微信用户"。
**这意味着：这一步无法在服务端伪造，只能在微信里真实点一次。**

于是让用户在小程序里**登录并打开首页**（服务端就会建立 openid↔手机号 绑定），然后立刻重测：

```
sspbigball → {"code":"0000","data":{"feeResource":{"feePersent":"22.00","dynamicFeeTitle":"剩余话费"},
                                    "flowResource":{"flowPersent":"306.78","dynamicFlowTitle":"剩余通用流量"},
                                    "voiceResource":{"voicePersent":"300","dynamicVoiceTitle":"剩余语音"}}}
getTicket  → {"code":"0000","data":"whtien1309067133a2b763adb528ce88ed39115e7..."}
```

**全链路打通。** 手机号从 `queryGoodsList` 的 `data.res[0].mainNumber` 拿到（11 位）。

## 阶段 5：明细接口（`mxx.client.10010.com`）放弃

旧集成的流量分项/账单/积分走另一套域名，需要 `ticket` + `ticketPhone`：

```
POST https://mxx.client.10010.com/servicequerybusiness/operationservice/queryOcsPackageFlowLeftContentRevisedInJune
form: ticket=<上面拿到的 ticket>&ticketPhone=<手机号>&ticketChannel=XCXYLCXYY&...
→ 999999（缺凭证）
→ {"msg":"用户信息获取为空！","code":"1001"}（补上手机号后依旧）
```

**小程序发的 `ticket` 不被这套接口接受**（它们是给联通 App / 另一套登录体系用的）。
既然小程序首页本来就是用 `sspbigball` 拿"余额/流量/语音"，就直接采用它 —— 于是有了本仓库的集成。

## 踩坑清单（速查）

| # | 坑 | 现象 | 结论 / 处理 |
|---|---|---|---|
| 1 | 明文 openid | `9999`，随机出现"调用异常"类文案 | 所有接口 `openid` 字段必须是 `RSA(token+openid)` 密文 |
| 2 | 密文长度 | 344 字符 base64 / 256 字节 | RSA-2048 + PKCS#1 v1.5 + base64 |
| 3 | 公钥来源 | 抓包里没有明文规则 | 解密 PC 微信 wxapkg → `app-service.js` 搜 `setPublicKey` |
| 4 | 明文构成 | `enc(openid)` 只对 `getToken` 有效 | `token + openid` 拼接，`token` 来自 `getToken`（要 URL 解码） |
| 5 | 未登录小程序 | `1002 获取用户绑定信息异常` | 先在微信里登录并打开首页（服务端建绑定）；`findMobileByOpenid` 需要 `wx.login` 的 code，无法伪造 |
| 6 | 请求头 | 缺 Referer/UA/xweb_xhr/X-Tingyun 易吃 `9999` | 照抄小程序：`Referer: https://servicewechat.com/<appid>/494/page-frame.html` |
| 7 | 字段大小写 | `sspbigball` 用大写 `openId` → `9999 首页大球调用异常` | `sspbigball`/`queryGoodsList` 用小写 `openid`；`getTicket` 用 `openId` |
| 8 | 服务端中文丢失 | `{"msg":"????ticket????"}` | 只能靠 `code` 判断（`1001` 鉴权失败 / `1002` 未绑定 / `9999` 兜底） |
| 9 | token 编码 | 直接用 `%2F` 形态参与拼接不确定 | 用 `urllib.parse.unquote()` 解码后再拼 |
| 10 | 明细接口 | `999999` / `用户信息获取为空！` | `mxx.*` 不吃小程序 ticket，暂时放弃明细 |
| 11 | 后端抽风 | 全站 `524`（Cloudflare 超时） | 与代码无关，等官方恢复（连官方小程序自己也 524） |
| 12 | 老集成的解析 bug | `'int' object has no attribute 'get'` | 响应结构变了（`data` 不是 dict），属旧代码健壮性问题 |

---

## 复现用命令

```bash
# 1) 看接口是不是活的（400/其它业务码 = 活的；524 = 官方后端挂了）
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' --max-time 25 \
  -X POST -H 'Content-Type: application/json' \
  -d '{"openid":"x","channel":"wxmini"}' \
  https://mina.10010.com/wxapplet/weixinNew/getTicket

# 2) 解密小程序包（见 tools/wxapkg_decrypt.py）
python tools/wxapkg_decrypt.py --appid wx56af9763578b9a93 \
       --file "%APPDATA%\Tencent\xwechat\...\__APP__.wxapkg" --out out/

# 3) 复现加密并验证链路（见 tools/rsa_probe.py）
python tools/rsa_probe.py --openid <你的明文 openid>
```
